What it takes

Change list — one migration + one registry

Migration
audit_events as a view over the six existing event tables + new columns on admin_audit (actor_type, target_type, severity, prev_hash, hash). notification_log gains channel, event, queued_at, delivered_at. auth_settings keys: authPolicy (lifetime/idle/lockout/password/mfaGrace/rememberDays), alertRules. No new tables except optional event_registry overrides (copy edits, channel toggles) — the registry itself is code in packages/shared.
Instrument
~20 new recordAdminEvent sites: failed sign-in + lockout, MFA enrol/reset, role & module grants, staff deactivate, CSV exports, impersonation/on-behalf, refund/void/manual payment, plan changes, template edits, bulk imports. Lockout middleware enforces the policy settings. Hash chain written on insert.
Endpoints
GET /audit/events (actor/target/category/severity/date, cursor paging, facets with counts), GET /audit/export (whole query, itself audited), GET/PUT /auth-policy, GET /sessions?kind=staff|client, POST /sessions/revoke-all, POST /auth/unlock, POST /staff/:id/mfa-reminder|mfa-reset|mfa-require, GET /notifications/catalogue, POST /notifications/test-send, GET /notifications/log (cursor), POST /notifications/:id/resend, GET /notifications/health, GET/PUT /notification-preferences (client + staff).
Behaviour
notify() reads notification_preferences before choosing channels — in-app always on for security/receipts, push/email per user flags, quiet hours hold push, daily digest batches opt-in events. Alert rules evaluated in the audit write path (5-fail lockout already exists in the worker pattern).
Deferred
LATER SSO/SAML surface, IP allow-list, digest scheduling UI, archive/cold-storage of audit rows, SIEM export. The registry + event stream are designed so each lands without re-plumbing.
