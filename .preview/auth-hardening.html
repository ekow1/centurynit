8 · What actually changes

Schema, config, endpoints, components

Schema — migration 0115

  • users.password_changed_at timestamptz
  • ops_users.mfa_required_by timestamptz grace deadline
  • trusted_devices user · label · ua hash · ip · expires · revoked
  • step_up_tokens or reuse settings-unlock row 15-min grant, action-scoped
  • admin_audit rows: mfa reset, trust revoked, step-up denied, new-device sign-in

Config + middleware reads

  • session.expiresIn / updateAge built from sessionDays / idleHours at boot + settings save
  • requireAuth idle check on lastActiveAt; minPasswordLength from policy in config + signup
  • HIBP k-anonymity at password set/reset when breachedCheck
  • requireRecentFactor(min) on refund/void/credit, role+capability, client delete, export, payout config
  • rotation: banner at <14d, gate at 0; grace: mfa_required_by banner → hard bounce

New endpoints

  • GET/POST /me/security — sessions, trusted devices, sign-ins, password change
  • POST /me/mfa/regenerate-codes · GET /me/mfa/codes.pdf · DELETE /me/trusted-devices/:id
  • POST /staff/:id/mfa-reset (reason → audited) · /sign-out-everywhere · /mfa-require-by
  • POST /auth/step-up — verify factor, mint 15-min token

Components + deferred

  • One MfaChallenge component (context: login-pending | session | enrol) — the two pages collapse
  • AccountSecurity page + user-menu link; sessions table → grouped/parsed/actionable
  • Login aside → context panel (what this screen is, who to contact, audit notice) — marketing blurbs die
  • Deferred: SSO/SAML, IP allow-list, hardware keys/WebAuthn, geo-blocking
