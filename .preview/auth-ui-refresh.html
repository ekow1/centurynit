MOCK · AUTH SCREENS — UI & POSITIONING REFRESH

Sign-in, invite accept, MFA challenge, MFA setup

The split-screen shell stays — it's the console's identity. What changes is what's in it: the aside stops being marketing and becomes context for this exact screen (who's signing in, what step, who to contact); the card gets a real hierarchy — context badge → title → lead → field group → primary action → secondary footer. Segmented OTP boxes replace the anonymous single input; the setup wizard gets a stepper in the rail and QR/secret side-by-side instead of stacked pages.

5 · The rules this sets

One layout grammar for every auth screen

Rail
  • · Brand + STAFF ONLY — always
  • · Context box for this screen (who, what, who to contact)
  • · Stepper on multi-step flows (invite, setup)
  • · Footer: audit notice, not copyright filler
  • · No feature blurbs anywhere
Stage
  • · Card centred vertically & horizontally, 400px (470px when QR/codes)
  • · Context chip top-right (STEP 2 OF 4)
  • · Exit link top-left, never under the card
  • · Loading = centred spinner inside the card's slot, not a blank page
Card
  • · Order: context badge → eyebrow → title → lead → banner/errors → fields → primary → meta → footer links
  • · One primary action, full width; alternates live in the footer row
  • · Segmented OTP boxes (6), auto-advance, paste-all
  • · Errors as banners above the form; lockout as a state card
