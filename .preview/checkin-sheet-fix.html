Why the sheet scrolled sideways, and the fix

Your screenshot shows the body shoved left with a horizontal scrollbar. Two rules combined: the helper text under Meeting link uses .hsheet__hint, which is white-space: nowrap — so a full sentence can't wrap and forces the body wider than the panel. And .sheet__body only declares overflow-y: auto, which makes overflow-x compute to auto too — so instead of clipping the overflow, the sheet scrolls to it. Every field is then wider than the panel and the whole thing reads offset.

The fix — three lines, two layers

Fix the sheet primitive so no sheet can do this again, then make the hint class safe outside a stacked row.

1 · packages/core/styles/base.mobile.css — the sheet body
.sheet__body { flex: 1; overflow-y: auto; + overflow-x: hidden; /* clip, never scroll sideways */ + min-width: 0; /* let flex children shrink */ + overflow-wrap: anywhere; /* a pasted URL can't force width either */ … }
2 · century-nit-ops/src/styles/scheduling.css — the hint
.hsheet__hint { font-family: var(--font-mono); … - white-space: nowrap; + white-space: normal; /* a sentence wraps; a row's short hint never needed nowrap */ } -.hsheet__row--stack .hsheet__hint { white-space: normal; } /* now redundant — drop */
3 · CheckInSheet.tsx
  • Nothing structural — the same JSX renders correctly once the two rules above land.
  • Optional tidy: the intro <p className="hsheet__hint"> becomes a plain muted paragraph so it isn't mono-tracked like a field hint.

Why fix the primitive, not just the sheet

The same .hsheet__hint lives in the Assign sheet, the Team sheet and the handoff sheet — they've survived only because their hints are short. And any sheet showing a pasted meeting URL, a long email, or an unbroken reference would hit the overflow-x gap the same way. Clipping at the body plus wrapping at the hint closes both doors.
