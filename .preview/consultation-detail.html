The call strip — and why it hides

Reported: the "Meeting link · LiveKit · In-app call" strip only appears after Start assessment is clicked. That's not a status gate in the template — it's a stale record plus a null render. Two small fixes make the call surface permanent and honest.

1 · Why it disappears

LayerWhat happens
Render gate
ConsultationDetail.tsx:543		 if (!meetingLink && !canManageMeeting) return null — for anyone who isn't the assignee or a manager, an online consultation with no link renders nothing. No "link mints on confirm", no placeholder — the surface silently isn't there. a11y/UX
Stale record
EnterpriseConsultations.tsx:291		 The detail renders the row from the cached consultations list — it never calls GET /consultations/:id on open (the endpoint exists; the page doesn't use it). A link minted by someone else's Confirm slot stays invisible until you mutate the row — and the first mutation most consultants make is Start assessment, whose replaceConsultation finally returns the fresh row with meetingUrl. bug
Join window
ConsultationCall modal		 The 10-minute join window only surfaces as a post-click error modal (MEETING_NOT_OPEN). The strip should say "Join opens at 09:20" before anyone clicks. feedback
Position The strip sits under the todo card, mid-pane, sharing a row with Resend/Change. For a confirmed online call, "where do I join" is the first question — it belongs directly under the header. layout

2 · The fix — one call block, four honest states

The strip renders for every online consultation, live or not, and says what is true right now. It never disappears; the action inside changes.
