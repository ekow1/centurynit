Portal · floating surfaces

The floats, audited

Four floating surfaces exist: the chat launcher + window (CommunicationCenter), the notification panel, and the toast stack — plus a dead second chat widget (FloatingChat.tsx, 555 lines, mounted nowhere). The plumbing underneath is genuinely good; the chrome on top is where it leaks.

What's working — keep it

  • ✓ Real-time is real. SSE drives message arrival, edits, deletes, reactions, typing indicators, and conversation status — no polling in the message path.
  • ✓ Channel routing is smart. Support / assigned officer / AI share one routed conversation; route({stageKey}) picks the right thread server-side.
  • ✓ AI → human escalation posts the transcript into the support thread — the applicant never re-explains.
  • ✓ Deep links work. ?chat=<id> and the open-chat event let any page or notification open the right thread.
  • ✓ Attachments stage → presigned PUT → bind on send. Resolved-conversation strip reopens on reply.

What's broken or weak

  • ✗ The unread badge is dead when closed. totalUnread comes from context, which is only fetched while the window is open (if (!open) return). A message arriving while the launcher sits closed never increments the badge — the one job a launcher has.
  • ✗ No presence. The officer tab can't say "Ama is online" — staff heartbeat presence exists server-side but never reaches the float.
  • ✗ The real chat window has no mobile layout. It's inline-styled width:360px; bottom:24px — on a 320–360px phone it overflows the viewport and ignores safe areas. (The responsive .chat-panel CSS targets the dead widget.)
  • ✗ Two divergent chat UIs. FloatingChat.tsx is dead code with its own tabs, bubbles and composer — drift waiting to happen.
  • ✗ Rounded bubbles vs. the square design language, ~400 lines of inline style objects, z-index 9999 floating free of the shell's layer scale (fab 890 / panel 1000 / toast 10000).
  • ✗ No Escape-to-close, no outside-click close, no minimize — the window is open or gone.

The unread-badge bug — the core functional fix

Why a new message never badges the launcher

loadContext() — the only thing that populates unreadCount — runs inside useEffect(() => { if (!open) return; ... }, [open]). Closed widget = no context = badge stays at zero. SSE chat.message events are subscribed in useCommunicationChat(open), which is also gated on open. So the float is blind precisely when it's closed.

Fix: keep a lightweight always-on subscription — the context fetch once on mount + a chat.message SSE listener that bumps unread when the window is closed, cleared on open. The heavy message list still lazy-loads on open. ~30 lines in the hook, zero API change.

Mobile rules

  • Full-screen sheet under 600px — the current inline width:360px;bottom:24px overflows small phones and ignores the tab bar; the new sheet uses inset:0 + safe-area padding like the app's other sheets.
  • Launcher respects --shell-bottom — sits above the bottom tab bar, never under a thumb.
  • Expand hidden on phones — the sheet is already full-screen; minimize drops to the launcher.
  • Peek card doesn't show on mobile — the badge + a heads-up row in the notification feed do the job; a floating preview over a small screen is noise.
  • z-index moves onto the shell scale: launcher 890, sheet 2100 above the tab bar, toasts stay topmost at 10000.

What changes in code

Functionality

  • Always-on unread: fetch context once on mount + SSE chat.message → bump badge while closed; clear on open. ~30 lines in useCommunicationChat.
  • Peek card: last inbound message preview above the launcher (closed state only, ~6s, localStorage "seen" guard).
  • Presence: reuse the staff heartbeat / conversation meta to render "Online · last seen" in the header.
  • Per-channel unread on tabs from the same context payload.
  • Esc / click-outside / minimize — window state machine: closed · open · minimized.
  • Delete FloatingChat.tsx — dead second implementation.

UI

  • Move ~400 lines of inline style objects into app.css as a .cchat block using shell tokens.
  • Header becomes the person (avatar + name + presence), not the word "CHAT".
  • Square bubbles — left-rule on theirs, solid on yours; read receipts in mono.
  • Context strip under tabs: chapter + relevant state.
  • Mobile sheet via media query on the real component; launcher uses the shell's --shell-bottom/--safe-* vars.
  • Toast stack unchanged — it's already disciplined; just lands on the shared z-scale.
