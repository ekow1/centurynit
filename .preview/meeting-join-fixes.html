"The meeting room opens at 08:45" shows as a stray line of text The window check works — the MEETING_NOT_OPEN 409 lands correctly. It just renders as inline joinError text wherever the button sits — easy to miss, no context. Polish
Join doesn't show on the ops consultation detail Bug. The ops case mapper renders the consultation type as "Online" (capitalized — useCasesApi.ts:62), but the detail page's meeting block only mounts when consultation.type === "online" (lowercase — ConsultationDetail.tsx:537, and the same check at :256). The entire meeting block — Join, resend, change — is dead code for every online consultation. Bug
No way to paste our own Zoom/Meet link instead of LiveKit The "Change / + Add Custom Link" editor exists but was hidden by the same bug. And a second bug behind it: setBookingMeetingUrl writes meetingUrl but leaves meetingProvider — paste a Zoom link on a LiveKit booking and /join still mints a LiveKit token, ignoring your link entirely. Also the editor pre-fills the input with livekit://…, which then fails the https:// validation. Bug
Portal still says "Book appointment" when a consultation is booked Three leftover CTAs: the /portal/appointments header always shows a primary + Book appointment; the consultant card on the booked consultation page has a Book call ghost that links back to appointments; the nav blurb reads "Book, reschedule, join". Nothing on those pages checks whether a booking already exists. UX
B · The "opens at" moment → a modal

Instead of a stray line under the button, joining outside the window opens a small dialog. The API's 409 already says when; we add the timestamp to the error body so the UI can show a live countdown instead of a frozen string. Same modal on portal and ops — it ships inside the shared useJoinMeeting hook, so every Join surface gets it free.

Meeting link

LiveKit · in-app
Save & email client Cancel

Pasting a link replaces the LiveKit room for this booking — the client gets the new link by email, and Join opens it directly. Clearing the field removes the meeting.

  • The actual fix is in setBookingMeetingUrl: setting a manual URL also writes meetingProvider: "manual", clears meetingSpace, and best-effort deletes the provider room. Without it your Zoom link is stored but /join keeps minting LiveKit tokens.
  • Draft pre-fill starts empty for token'd providers (a livekit:// handle isn't a link and would fail validation anyway).
  • Round trip: clearing the link doesn't resurrect a provider room — "Generate" stays the way back to an auto room.
E · Portal — stop offering a booking that exists
