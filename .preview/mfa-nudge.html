MFA nudge — ask until it's on, let them skip

The plumbing already exists — MfaPrompt in the portal layout, a full setup wizard at /portal/security, and a status endpoint. What's missing is the ask: a quiet banner nobody reads, and a whole class of users — social-only accounts — for whom every surface literally says "Not applicable". This mock is the nudge ladder on top of the existing pieces.

Gap B — social accounts get "Not applicable"

SecurityGOOGLE ACCOUNT
Sign-in methodGoogle
2FA statusNot applicable DEAD END
Set up 2FAbutton hidden

applicable = hasPassword || enrolled — a Google-only user holds no password here, so the banner hides, the button hides, and enrolment (which verifies a password) can't run anyway. Your exact complaint: no way to turn it on.

The honest fix for social accounts: enrol via email code — the second factor is a code to the account inbox at each sign-in, verified without a password (the account itself proves ownership). Authenticator-app stays available if they first set a password — so the Security card offers both: "Secure sign-in with an email code" primary, "add a password to use an authenticator app" secondary.

Three surfaces, one state machine: GET /auth-settings/mfa → enrolled · applicable · required. The sheet and the banner are the same component at two weights — the sheet for the first authenticated visit of an account, the banner for every session after. Nothing new to build server-side except the passwordless enrol path.

nudge 3
  • Copy earns its place — states the risk ("one password away") and the cost ("two minutes"), not the generic "protect your account".
  • The skip says what it does — "remind me next sign-in" removes the surprise; persistence is a promise, not nagging.
  • nudge N counter — a small mono chip counting dismissed sessions. Quiet accountability: by the fifth visit the user knows we mean it. Stored server-side (mfa_nudge_count or derived from a dismissals table) so it survives devices — sessionStorage stays only for "hidden this tab".
  • Required accounts (portal.mfa_required) — same banner, no skip, amber-free (monochrome): the count chip swaps to required.
