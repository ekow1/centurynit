What changes vs today

  • Settings honoured. The login page reads /auth-settings: Google button appears when ops.google_sso is on (today it never exists), password form disappears when ops.email_password is off (today it always shows, and sign-in still works — the toggle is decorative end to end).
  • Staff-email check moved. The debounced "is this email staff" call is an enumeration oracle that also scolds typos pre-submit. It stays on forgot-password (prevents a dead send), leaves sign-in.
  • MFA challenge resumes. A pending two-factor cookie on load jumps straight to the code screen. Today refresh resets you to the password form mid-challenge.
  • Invite acceptance branded + prefilled. Same split shell as sign-in; name prefilled from the invitation (today the controlled input ignores defaultValue and renders empty); "Already have access? Sign in" escape; correct verb for existing-login accounts ("Join" not "Create account").
  • MFA setup honest. Method list filtered by ops.mfa_methods (enforced server-side too), "required" copy follows ops.mfa_required, done routes to ROLE_HOME not hardcoded /dashboard, and already-enrolled users get a manage state instead of a misleading "You're all set".
  • One shell, one password UX. Show/hide eye, strength meter, live match hint, 12-char rule stated once, identically across invite, reset and any future credential screen. Forgot/reset get the features aside back; © year computed, not hardcoded 2026.
