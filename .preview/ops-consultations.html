Ops — Consultations: the 23rem problem

Screenshot: a full consultation detail — tabs, required-docs checklist, request form, verify actions — crammed into a rail that was built for a compact “now” summary. Plus the same chip wall we just removed from Workspace.

Diagnosis:
  • The pane is pinned at 23rem forever. Consultations passes rail= to CaseScaffold → cn-scaffold--rail fixes the detail at min(23rem, 38%). The --open rule that would widen it only fires with collapseDetail, which this page doesn't set. So a selected record — the full ConsultationDetail — is squeezed into a rail designed for four ops-dkv stats.
  • Nine status chips + Everyone/Mine + search — identical disease to the Workspace wall we shipped a fix for yesterday. Seven of nine chips read 0.
  • The selected row is a full-ink inversion — 110px of solid black for a selection state. The detail pane already says what's selected.
  • “1:00 AM” booking — dateTime formats startsAt in the branch timezone. Either a 1 AM slot was actually offered, or a booking was written off-path. Worth flagging, not hiding: render the branch time explicitly and flag off-hours slots.
  • “Requested from the client” is a comma-separated free-text box — typos become permanent request names, and the client sees whatever was typed.
  • Uploaded doc reads “Invoice-NCIRADXY_0003.pdf · passport” — the file is labelled by declared type with nothing flagging the name/type mismatch.

    What changed:
  • The pane opens. Nothing selected → the “Today” rail keeps its 23rem. A record selected → the detail takes the flex width (list narrows to ~30%). One CSS rule + emitting cn-scaffold--open whenever detail !== null, not only under collapseDetail.
  • Chip wall → one scan row. All · Needs action · Today · Mine + search + Filters ▾ holding the seven status facets — same drawer pattern shipped on Workspace, same URL params (status, owner, branch, q unchanged).
  • “Needs action” is a real cut — Under review + reschedule-asked folded into one facet, so the two states that demand a manager aren't scattered across zero-count chips.
  • Selection loses the ink wall. Left bar + inset ring instead of full inversion — consistent with the bare scaffold's selection language.
  • Rows say more in less height. Time is labelled with its zone (“01:00 Accra”), doc-review and missing-handler surface on the row, and off-hours slots get a flag instead of silently looking normal.
  • Doc requests become a checklist. Standard document names as chips (+ a free-text “other”), so the client sees canonical names, not typos. Rows show “declared as X — filename suggests otherwise” when name and type disagree.
  • The bar carries the record. CRS-2026-0001 · Confirmed in the pane bar — identity survives scroll, Expand/Close unchanged.
