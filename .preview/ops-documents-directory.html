Documents — a directory per client

The problem: today the page is a review queue wearing a folder costume — the same client can appear twice (once under "Waiting for review", again under "Reviewed this week"), their files are split across those bands, and the rest hide behind an "All folders ▸" toggle. There is no place that answers "show me everything this client has ever uploaded."
The proposal: the page becomes a filing cabinet. Each client is one directory. Inside the directory, one folder per application (case reference) plus a General tray for anything unattached. Files keep their review actions and the preview pane — only the shape changes.

One client, many cards — Efua's pending files sit in band 1, her verified ones in band 2. Nobody can see her file set as a whole without holding it in their head. The archive is a second-class citizen — "All folders" renders folded; finding a client's old passport means expanding the backlog and reading every card. No per-application grouping — a client with two applications (e.g. a school case + a visa case) mixes both sets of files on one card with no divider. Eleven chips again — status chips and category chips at equal weight; the six categories are occasional cuts, not triage.

  • One row per client — always. The directory is the unit. Pending count, case refs, file count and last-upload all read on the closed row; nothing about a client is split across bands.
  • Sort: directories with pending files first (oldest pending first), then rejected-needs-reshoot, then the clean archive A–Z. The review queue survives as ordering, not as a second layout.
  • It reads like a file manager — every directory carries a real folder glyph (drawn in borders, filled when open), a ▸/▾ caret, and its contents sit inside a tree rail so the nesting is visible at a glance.
  • Chevron opens inline — or the row drills into a full directory view (03). Either way the state is a URL param: ?client=…&doc=… makes a file a deep link.
  • Chips shrink to three — All · Pending review · Mine. Status + categories move behind Filters ▾, same drawer pattern as the worklist.

  • Subfolder = case reference, rendered as a folder. The API already returns caseReference on every document — the folders are free. Anything without one lands in General instead of inventing a fake case.
  • Files carry the folded-corner page glyph with their type stamped inside (PDF / JPG / DOC) — a reviewer can spot "the passport scan" by shape before reading a name.
  • Within a folder, files group by category (Identity → Academic → Language → Financial → Professional → Other — the existing CATEGORY_ORDER), newest first inside each.
  • The detail pane is unchanged — same inline preview, same Verify/Reject actions, same review note display. Only the left side gets the directory shape.
  • Breadcrumb Documents / Efua Owusu returns to the index; the closed row chevron is the same view inline for a quick peek.
