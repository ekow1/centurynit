Ops · journey-scope audit

Two vocabularies are running side by side

The product now speaks Stage 0 Consultation → I Admissions → II Visa → III Departure, scoped per client (included / skipped / recommended). Ops still renders the old six-chapter model (Consult → Enrol → Apply → Visa → Depart → Done) almost everywhere. What breaks, page by page:

Drag-advance can push a scoped case into a stage it never bought.Gap

Fix 1 — the board speaks the journey

Rail becomes 0 Consultation → I Admissions → II Visa → III Departure → Done. Columns collapse to stage lanes (multiple old sub-stages group under their stage). Every card carries a scope chip + mini route: amber dot = consultation done, ink = in plan, hollow = skipped, amber-outline = recommended. A lane the file skips is ghosted, not treated as a gap.
