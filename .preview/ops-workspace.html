The Workspace — what I'd change

The bones are right: greeting, two tabs (Worklist / Caseload), a queue table, and the Now rail that surfaces the live consultation. What needs work is the wiring — URL state that goes stale, chips wearing the wrong ARIA role, rows a keyboard can't select — and a few pieces of information that exist in the code but never reach the screen.

1 · Defects in the current page

WhereWhatFix
useCaseTab (CaseTabs.tsx:26) The ?tab= mirror only re-derives on [recordKey, preset] — a deep link that changes the tab while the page is mounted does nothing. filter has the same bug: it reads searchParams once in useState. bug Derive from the URL at render; no state, no effect. Same pattern for filter.
Queue chips (Workspace.tsx:322) Filter chips are marked up role="tablist"/role="tab". They don't switch panels — they narrow a list. A screen reader announces "5 tabs" and selects one that does nothing of the sort. a11y One role="radiogroup" + role="radio" aria-checked (single-select), arrow-key navigation comes free in the pattern.
Queue rows (PendingTasks.tsx:199) <tr onClick> with no tabIndex, no key handler — the preview pane is unreachable by keyboard. Selection and overdue are inline style, so no theming and no :focus-visible ring. a11y tabIndex={0} + Enter/Space, or a real button in the title cell. Classes q--sel/q--over instead of inline styles.
stats.counts (Workspace.tsx:236) "today" and "overdue" counts are computed every render and never rendered — the two most useful filters don't exist as chips. dead work Either render them (proposed below) or delete the computation. Don't compute what the UI can't show.
URL state ?filter= is in the URL; typeFilter, branchFilter, dateSort and the selected task are not. Refresh loses three of four filters and the open pane; a notification can't deep-link a task. consistency All of it in the URL: ?tab=&filter=&type=&branch=&sort=&open= — the app already deep-links invoices this way (?open=inv-…).
Header (Workspace.tsx:297) An empty flex <div> with a comment — the filters moved, the div stayed. The overdue-invoice stat is meanwhile buried at the far right of the filter row. dead UI Delete the div; promote the stat into the header summary (mock below).
Assign dispatch doAssign (list) and placeHandler (preview pane) implement the same kind-switch twice — they can drift, and already differ in error handling. drift One assignTask(task, to, placement) in lib/pendingTasks.ts that both call.
*Details blocks Nine components of <p><strong>Key:</strong> value</p> — a definition list wearing paragraphs. markup A shared <FactGrid> rendering a real <dl>: less code, better semantics, consistent rhythm.

3 · The code that changes

// useCaseTab — the URL is the state; deep links work while mounted
const urlTab = searchParams.get("tab");
const tab = isId(urlTab) ? urlTab : (preset ?? fallback());
const setTab = (next: T) => setSearchParams(prev => {
  const p = new URLSearchParams(prev); p.set("tab", next); return p;
}, { replace: true });

// the same pattern fixes ?filter= — and setFilter stops capturing stale params
const filter = searchParams.get("filter") ?? "all";
const setFilter = (next: string) => setSearchParams(prev => {
  const p = new URLSearchParams(prev);
  next === "all" ? p.delete("filter") : p.set("filter", next);
  return p;
}, { replace: true });

// selectable rows the keyboard can reach
<tr tabIndex={0} aria-selected={selected}
    onClick={() => onSelect?.(t)}
    onKeyDown={(e) => { if (e.key === "Enter" || e.key === " ") { e.preventDefault(); onSelect?.(t); } }}
    className={`q-row${selected ? " q-row--sel" : ""}${overdue ? " q-row--over" : ""}`}>

Nothing above needs new dependencies or API changes — it's wiring and semantics inside Workspace.tsx, PendingTasks.tsx, CaseTabs.tsx and a few lines of CSS. The one structural piece is lifting assignTask into lib/pendingTasks.ts so the list and the pane stop diverging.

4 · The Caseload tab

Same data, different question — "who is carrying what" instead of "what needs doing". The view is good at answering it, but it carries the same ARIA and URL problems as Worklist plus a few of its own.

WhereWhatFix
View toggle (WorkspaceCaseload.tsx:265) "By officer / By stage" doesn't change any grouping — it only hides the officer panel. The bands below are identical either way, and a manager in "By stage" has no way to filter by officer. mislabeled Delete the toggle. The officer strip stays always on and is the by-officer view; an Officer select joins the filter row so both views can narrow by person.
Chips (line 448) Same role="tablist"/role="tab" misuse as the Worklist chips — these filter, they don't switch panels. a11y radiogroup/radio, same component as the queue filter.
URL state Nothing persists: chip, staff, branch, view, showCompleted are all local. Refresh loses the officer you were inspecting. consistency ?chip=&officer=&branch= in the URL — and now "Kofi's stalled cases" is a linkable view.
Officer pane The officer record (load, week hours, carrying, handoffs) lives in a cramped ~19 rem aside that squeezes the list it's supposed to filter. layout Officers become a horizontal strip of load cards; the record opens in the Sheet the app already has — full detail, no squeeze.
Stats shown twice The dash-day row (top) and the filter-row footer both say "N cases · N consultations · N officers · N stalled". noise Keep one — the top line. The footer line goes.
ops-steps dots aria-label on a plain <span> is ignored by AT — the progress reads as nothing. And a consultation's 3/4 dots look identical to a case's 5/7 though they mean different scales. a11y role="img" aria-label="Step 3 of 4" — or print "3/4" next to the stage label, which sighted users benefit from too.
UnassignedQueue Triage sits between the officer panel and the bands — the one thing demanding a decision is mid-page. order It goes first, under the stats line. Nothing is more urgent than a record nobody owns.
Client cards Not selectable — only "Open →" navigates away, while the Worklist's rows preview in place. Two queue cards, two behaviours. consistency Card click selects → the same PreviewPane detail the Worklist uses. The task is already built; caseload just doesn't select it.
staffHours fetch Fetched on mount even when no officer is ever selected. perf Lazy: fetch on first officer select.
