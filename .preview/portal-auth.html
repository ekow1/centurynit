Portal sign-in — /start (StartJourney)

The portal auth page is functionally rich — password, Google, email-code, MFA, signup-verify, reset — but the structure buries it under two stacked tab systems, defaults every visitor to a Google-only tab, nukes the whole page on every submit, and the password-reset flow is broken end-to-end: the email sends a link back to /start?token=…, but the page never reads ?token — it asks the user to "paste the reset token" that the email never displays. Anyone who clicks the link lands on the sign-in form with the token ignored.

Build notes
  • One tab system: delete the inline-styled Log In / Sign Up underline row — the boxed .auth-tabs segmented control becomes the only switcher. The "Social" tab dies; Google is a button on the main form.
  • Kill the full-screen loading-overlay — button-level loading text only. The page never leaves.
  • Read ?token= in the search-param effect (it already handles ?verified/?error) → setStep("set") with the token in state.
  • OTP component: six <input maxlength=1> cells with auto-advance + paste-split; reused for email-code, signup-verify, and MFA TOTP.
  • MFA frame: identity strip (● email · step 2 of 2) under the title; the method label + hint carry the active method; a labelled divider + link row below the CTA offers the other routes — current method excluded.
  • New endpoint GET /auth/mfa/method (~20 lines, no auth middleware): read the better-auth.two_factor cookie → look up verifications where identifier = cookieValue → value is the user id → return { method, maskedEmail }. Missing/expired → 401 → frontend falls back to the TOTP challenge. This is the same lookup verify-totp performs — the cookie is already the proof-of-password artifact.
  • Portal challenge flow: on entering mfa_otp, fetch the method → if email_otp, render the email challenge and fire send-otp once automatically → if totp, authenticator boxes as today. The masked email in the hint comes from the endpoint, not from client state.
  • Trust device: checkbox state → pass trustDevice: true in verifyTotp/verifyOtp/verifyBackupCode bodies. The plugin sets the trust_device cookie (30-day default, configurable via trustDeviceMaxAge).
  • Ops gets the same fix: replace the broken getMfaEnrollment() call in the twoFactorRedirect branch with this endpoint — that's what makes the email_otp auto-send path actually reachable, and it lets us delete the dead fallback branch.
  • Error honesty: map Better Auth's TOO_MANY_ATTEMPTS_REQUEST_NEW_CODE to "too many attempts — sign in again" instead of the generic "code not accepted".
  • Copy fixes: verify_email eyebrow → "Check your inbox"; sub interpolates signupEmail; "6-digit code" not "link"; reset minimum → 12 (matches the real minPasswordLength); success mark → ✓.
  • Password checklist component: a PwChecklist next to the input — required rule inverts on password.length >= 12, suggestions (not your name or email, four random words beat symbols) stay hollow and never block submit. Submit stays disabled until the required row inks. Confirm-password gets a live "don't match yet" line under the field.
  • Chapter list uses real vocabulary: Roman numerals I–VI and the actual blurbs from CHAPTERS in packages/shared/labels.ts — VI is "departed · post-arrival plan", not an alumni metaphor (this is a consultancy, not a school).
  • Mono Google mark: bordered square "G" — the four-color SVG is the only non-monochrome element on the page.
  • One backend addition — GET /auth/mfa/method only. Every flow otherwise already exists (Better Auth email/password, Google OAuth, email OTP, TOTP/email/backup MFA, trust device, token reset).
  • Mobile: brand panel already collapses — unchanged.
