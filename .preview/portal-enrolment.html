Portal — Chapter II · Enrolment: the GH₵1 package problem

Screenshot: funding-track cards render GH₵1 ($0.05), GH₵5 ($0.35) — a $0.05 consultancy package, a deposit of a few pesewas, and a “Pay the deposit” button for essentially nothing.

Diagnosis — three separate faults, one screen:
  • Data (root cause): the live service_packages rows hold price_cents = 5, 33, 33 — literally $0.05 / $0.33 / $0.33. The seeded $1,500 / $2,000 / $2,500 were overwritten — someone typed 0.05 into the ops “Price (USD)” field, which multiplies by 100 into cents.
  • Portal: priceCents > 0 is the only guard, so $0.05 overrides the honest computed fee. Deposit = 10% of it → GH₵0.08. The page also ignores the package’s currency column entirely — pesewas would render as dollars too.
  • Ops editor: “Price (USD)” accepts any number with no floor, no preview of what the client will see, no confirm. Saving $0.05 succeeds silently.

    • The fix is two-layer: repair the rows + guard the write (ops validation, currency respected), and render honestly — a package priced below a sane floor shows “pricing being updated”, never GH₵1.
