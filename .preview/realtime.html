What is live today, and what isn't

The stream and the publisher exist. Three wiring gaps keep some screens on the 30-second poll.

SurfaceTodayWhy / what changes
Chat (both apps)livechat.* events on the shared stream — messages, typing, reads, reactions.
Ops pipeline · Workspace · CasesmostlySSE → debounced refetch, but the whitelist misses ~15 event types (invoice_*, payment_recorded, school_*, consent_decided, handoff_opened…). Switch to prefix matching.
Portal journeymostlySSE → syncFromServer(), but only fires when a notification exists. Silent field updates wait for the 30s poll. Domain events fix this.
Ops invoices / paymentsfetch onceuseInvoiceApi has no SSE listener — a Paystack webhook payment stays invisible until reload.
Ops work queue · leads · bookingsfetch onceuseWorkQueue loads leads/bookings on mount; lead.new / booking.new never reach it.
Second console open, same casestaleStreams are per-user (user:{id}:events); updates only reach staff the code enumerated. Add the ops:events broadcast channel so every open console hears every case event.
Notification bell noiseside effectbroadcastCaseUpdate uses notify() as a transport — every field edit writes a bell row + web push. Split refresh signals from notifications.

The build, in order

Smallest change that makes everything live — no new infra, no websockets, no new deps.

  • Split signal from notification. New emitDomain(type, payload, {userId?, ops:true}) in worker/pubsub.ts — pure Redis publish, no DB row, no push. notify() keeps doing bells+push+email; refresh signals stop piggybacking on it. century-nit-api/src/worker/pubsub.ts
  • Add the ops broadcast channel. The ops stream subscribes to ops:events alongside the user's own channel (role check already on the stream). One publish reaches every open console. century-nit-api/src/routes/events.ts
  • Emit from every mutation. Call sites in cases / applications / invoice / payments (incl. the Paystack webhook) / schools / documents / bookings / journey publish a domain event after the write — case.updated stops writing bell rows, becomes a pure signal. century-nit-api/src/services/*
  • One stream per tab, both apps. Fold useOpsNotifications onto the useOpsSSE singleton — today ops opens two EventSources. century-nit-ops/src/hooks/useOpsNotifications.ts
  • Prefix matching, not whitelists. Ops: refresh on case.|application.|stage.|invoice.|payment.|booking.|lead.|school.|document.|handoff.|travel.|consent. Portal: journey prefixes already exist — extend to the new domain events. useCasesApi.ts · AppState.tsx
  • Wire the dead surfaces. useInvoiceApi and useWorkQueue (leads + bookings) subscribe to useOpsSSE with the same 1.5s debounce. useInvoiceApi.ts · useWorkQueue.ts
  • Keep the 30s polls as the fallback. They already exist — SSE drop, sleeping tab, Redis outage all degrade gracefully, exactly like today.
