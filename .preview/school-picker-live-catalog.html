School picker — pull from the live catalogue, not the bundle

Two diagnoses, one fix. (a) The portal's Chapter III school picker renders the static catalogue bundled into the JS (packages/core/src/content.ts — universities, programs, filterProgramsForPackage) — frozen at build time, blind to everything ops does in the catalogue. (b) Ops's own modal calls the live endpoints but the server ignores ?destinationId= / ?universityId= — every select shows the full list.

So it half-works by accident. The bundle and the seed share slugs, so lookups resolve — but the picker can't see anything ops adds, edits, or deactivates. One catalogue change and the portal offers ghost schools; the freeze-snapshot then writes universityName: null with no error. The fix isn't syncing the two — it's deleting the second source.

Same markup, live source. The cascade reuses useAssessmentCatalog() — already in the file, already hitting /catalog/destinations · /universities · /programs for the booking flow. Changes:
  • Country filters universities by destinationId; university filters programmes; programme fills intakes + tuition from the live row (tuitionUsd → formatDualCurrency).
  • is_active = false rows never render — ops controls the list in one place.
  • Package gate still applies: filterProgramsForPackage logic runs on the live rows (level + funding track).
  • Empty states are honest — "No programmes listed for this university yet" — instead of the static fallback programs[0] silently substituting MIT.
  • Submits real catalogue ids → the server's freeze-snapshot always resolves.
    • Loading + failure. While the catalogue loads the selects render skeletons (); a failed fetch shows "Couldn't load the school list — retry" instead of an empty dropdown that looks like the catalogue is empty.
