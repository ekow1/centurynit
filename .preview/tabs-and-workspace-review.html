Review · monorepo + tab systems

The workspace and the tabs

The architecture is genuinely good — two Workers, one API, the journey derived in one pure function. What needs attention is the debris left by past design passes and three overlapping tab implementations that disagree with each other and, in one case, with the URL.

2 · The tabs — three implementations, one job

Tab-like selection is implemented three different ways, and the styles and the components live in different packages:

ImplementationComponentStylesUsed by
Underline strip ops/pages/case/CaseTabs.tsx core/styles/components.css Workspace, ConsultationDetail, and raw .cn-tabs markup in EnterpriseApplicants
Chapter chips ops/pages/case/CaseSpine.tsx ops/styles/scheduling.css CaseDetail only
Ad-hoc pills inline ops-pill + role="tablist" scheduling.css ~15 list filters across the ops app

The component lives in century-nit-ops but its stylesheet lives in packages/core — so the portal could not reuse the strip even if it wanted to, and the chip styles hide inside a file named for a different feature. Move CaseTabs/CaseSpine into century-nit-core/ui next to their styles. The hook keeps the router, so it stays in the app (or takes injected get/set callbacks) — core has no react-router dependency today and shouldn't grow one for this.

The bug: useCaseTab ignores the URL it claims to mirror

The hook's whole purpose is deep-linking — "a notification or a handoff can deep-link to a chapter". But the re-derivation effect depends on [recordKey, preset] only, so if ?tab= changes while the detail is already mounted — exactly what a deep link does — the tab stays stale.

// today — state copies the URL once, then stops listening
const [tab, setTabState] = useState<T>(derive);
useEffect(() => setTabState(derive()),
  [recordKey, preset]);  // urlTab is read but not a dependency

// proposed — the URL is the state; nothing to sync
const urlTab = searchParams.get("tab");
const tab = isId(urlTab) ? urlTab : (preset ?? fallback());
const setTab = (next: T) => setSearchParams(prev => {
  const p = new URLSearchParams(prev); p.set("tab", next); return p;
}, { replace: true });

Deriving at render kills the effect, the eslint-disable comment, and the whole class of "URL and state disagree" bugs — while making every deep link work, including browser back. fallback() runs each render but is a pure lookup; cheap.

Smaller defects

WhereWhat
CaseSpine"VI Complete" is a <div aria-hidden> inside role="tablist" — screen readers are told the row has a tab that isn't there, and sighted users see a state AT never hears. Make it a real disabled role="tab", or move it out of the list.
CaseSpineThe "now" chip gets its meaning from ::before and a title — a sighted-mouse-only signal. Give it aria-current="true" and put the lock/unlock hint in aria-describedby, not just title.
CaseTabsThe lock is a 🔒 emoji — the only emoji in a monochrome mono-font interface. A dashed border + "—" marker (as below) says the same thing in the system's own language.
PortalSections ledgerTwo rows are numbered "V" — the pre-departure milestone and the ticket. The numeral is the chapter system; a second V silently breaks it. The ticket is part of chapter V, so it should carry no numeral (indent it under V) rather than repeat one.
MobileTabBar"Login" links to /start — the journey funnel, not sign-in. If the funnel is intentional the label lies; if not, the route is wrong.
ConsultationDetailUses the underline strip while its sibling CaseDetail uses chips — same app, same job, two visual languages. A consultation is a short sequence too (Background → Decision), so it can take the spine with two nodes.

3 · The proposal — one tab family, two densities

One component in century-nit-core/ui: <Tabs> for flat sets (Workspace), <ChapterTabs> for ordered journeys (case, consultation). Same lock/active/ current semantics, same ?tab= hook underneath. Below: today's spine, then the proposed one.

Today — chips, dead end-cap, no progress

VI Complete

Nine floating pills. Passed/now/locked read only through border styles; the end-cap is a div that fakes a tab; nothing says what "now" means without a hover; wraps awkwardly on narrow screens.

Proposed — a connected track, states spelled out

VI · Complete

The nodes touch — the track is the timeline. Each carries a status line in words, not just border style: "done", "in progress · viewing", "locked · needs an admission". The end-cap leaves the tablist. Money/Docs keep their counts. Sticky, and scrolls with snap on narrow screens instead of wrapping into a pile.
