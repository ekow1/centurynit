Kind vocabulary — already in the data

caseCommentSchema.kind is one of comment · recommendation · document_request · status · assignment. The API already writes it; the UI just never reads it.

Mobile — the rail survives, the chrome doesn't

At <960px the card goes full-width with no outer padding, the head row wraps (chip drops to its own line), the marker shrinks and the rail hugs the edge, and "x new" collapses to a dot count. Action links grow to full-width tap targets. Nothing is hidden — a phone client sees every update a desktop client sees.

rules @media (max-width:959.98px) — same breakpoint as the app shell

.upd-card  →  margin:0 −.85rem; border-left/right:0 (full-bleed inside the page pad)
.upd__who  →  dropped: on mobile the author is the card title ("Updates from Ama"),
             one name per row is noise
.upd__when  →  relative only ("2h ago", "5d"); the date moves into a title attr
.upd__mark  →  .48rem; rail shifts to left:.35rem — thinner but unbroken
.upd__act a  →  display:block; padding:.45rem 0 — 44px-tall tap target
.upd-card__count  →  bare number, no "new" label
.upd__body  →  webkit-line-clamp:3 on long notes; the sheet shows the rest

The one layout change that matters: the author name leaves the row. On a phone, "Ama Serwaa" repeated on every line costs more than it informs — the card header already says whose updates these are.

Empty state — currently the section just vanishes
