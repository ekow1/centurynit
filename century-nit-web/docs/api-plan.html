Migration Plan · Proposed

Century NIT API Migration

Moving a complete, working product from eighteen localStorage keys onto a documented HTTP API — without rewriting the interface that proved it.

Stack Hono · Zod/OpenAPI · Workers Store Neon Postgres Docs Scalar at /api/docs

01 Where we are

The application is finished and functional with no server. Every piece of state lives in the browser.

SurfaceToday
Worker5 lines — one stub returning {name:"Cloudflare"}
HonoAlready a dependency (4.11.1)
API routingwrangler.json already sets run_worker_first: ["/api/*"]
Persistence18 localStorage keys
Mutations104 — 62 ops, 42 portal
Domain types~70 exported TypeScript types
AuthNone — role switching only

The schema already exists. Invoice, SchoolApplicationTrack, Lead, MockConsultation, InternalTicket and some sixty-five others are fully specified and proven through the UI. This is a persistence and authorization exercise, not a data-modelling one.

Not a migration task — a live exposure

ROLE_PERMISSIONS is enforced in React only. Anyone can open devtools and grant themselves admin. That is fine for a prototype and unacceptable the moment a server holds real data.

Phase 2 exists to close this. No phase that exposes applicant data should ship before it.

02 Architecture

React SPA
Interface unchanged. A repositories/ seam calls localStorage today, fetch tomorrow.
↓ /api/*
Cloudflare Worker · Hono
Routes, Zod validation, generated OpenAPI, Scalar docs, JWT and role middleware, audit trail.
↓ Hyperdrive pooling
Neon Postgres · Cloudflare R2
Fourteen tables. R2 holds document uploads.

Swagger is generated, never written

One Zod schema per resource produces four artefacts from a single definition: 

Zod schema ──┬─→ runtime validation   request + response
             ├─→ TypeScript types    z.infer
             ├─→ OpenAPI 3.1         /api/openapi.json
             └─→ Scalar docs         /api/docs

Hand-written OpenAPI is a second source of truth that nobody updates. Generated OpenAPI cannot drift, because the object serving the request is the object describing it.

Schemas live in src/shared/schemas/ and are imported by both the worker and the React app. A breaking API change then surfaces as a TypeScript error at build time rather than a runtime bug in production.

Decisions worth stating

Money is integer cents in USD. GHS_RATE stays a presentation concern. Never store a formatted string — that exact mistake already produced the "GH₵45,000 / $3,000" → 450003000 bug that inflated every finance total into the billions.

Enums become Postgres enums, not free text: ApplicationStatus, VisaStage, InvoiceStatus, DocUploadStatus, ProcessStageId, SchoolTrackStatus, LeadStage, TicketStatus.

Seed content stays in content.ts for now. Destinations, universities, programmes and scholarships are read-mostly, and the CMS overlay already anticipates the swap — resolveRecord() reads override ?? seed, so moving the seed into tables later changes one function rather than every page.

OpsDirectives and liveOverlay do not become tables. They are artefacts of the localStorage simulation bridge. Once ops and portal read the same database they disappear entirely.

04 Endpoints

104 mutations do not become 104 endpoints. Grouped by resource, with state transitions modelled as commands rather than a generic PATCH.

Why commands, not CRUD

voidInvoice, recordInvoicePayment, assignConsultation and rescheduleConsultation each carry intent, validation rules and an audit entry. PATCH /invoices/:id {status:"void"} discards all of that and lets any client write any state. Commands keep the invariants on the server. CRUD for records, commands for transitions.

05 Authentication & authorization

Tokens

Short-lived access JWT (15 minutes) plus a refresh token, both in HttpOnly; Secure; SameSite=Lax cookies — not localStorage, where a single XSS is a total compromise.

Two audiences

applicant tokens are scoped to their own rows and reach only /api/me/*. staff tokens carry a role and are checked against the permission matrix.

Reuse the existing matrix

ROLE_PERMISSIONS moves out of OpsAuthContext.tsx into shared code and becomes Hono middleware. Its structure is already right — five roles, explicit module lists, deliberately disjoint so admin has no window into applicant data. It only needs to run where the user cannot reach it. 

app.use("/api/invoices/*", requireStaff, requireModule("invoices"));

The React copy stays, but only to hide UI. The server becomes the authority.

Row-level scoping

Consultants see only cases assigned to them; managers and coordinators see all. That predicate exists today as roleScopedConsultations and must be reimplemented as a SQL WHERE, not a client-side filter.

06 Phasing

Each phase is independently shippable. The order matters: Phase 2 gates everything that touches applicant data.

  1. 00
    Repository seam
    Frontend only, no backend. Interfaces the UI calls instead of touching context state directly — localStorage on day one, fetch per module later.
    Ships nothing visible. Makes every later phase a small diff.
  2. 01
    Foundation
    @hono/zod-openapi and Scalar, src/shared/schemas/, /api/health, error envelope, request IDs, and a CI step that publishes the spec.
    Exit: /api/docs renders, one endpoint validated end to end.
  3. 02
    Auth
    Neon schema for users and sessions, login, refresh, JWT middleware, ROLE_PERMISSIONS server-side, row scoping.
    Exit: a staff token cannot read a module its role lacks.
  4. 03
    Content
    CMS overlay and published content. Read-mostly, lowest risk, and it proves the whole pattern including overlay resolution.
  5. 04
    Invoices & payments
    Highest business value, cleanest boundaries, and freshly refactored — the command surface is already correct.
  6. 05
    Consultations & applications
    The largest surface, including school-application tracks and offer terms.
  7. 06
    Tickets, notifications, documents
    Documents need R2 and presigned uploads — today updateAssessmentDoc stores only file.name, so no real file has ever been uploaded.
  8. 07
    Retire the simulation
    Delete OpsDirectiveBridge, the autopilot timers, resetOpsState and the OPS_STATE_VERSION guard. Replace cross-tab sync with SSE against the real source of truth.

07 Risks

The simulation timers are load-bearing. AppState advances consultations and school tracks on setInterval. Real backends do not self-advance. Phase 5 must replace them with genuine ops actions, or the demo silently stops working.

Two naming conventions already disagree. OpsDirectiveBridge translates "installments" ↔ "installment" and VisaStage ↔ VisaStatus. Reconcile these in the shared schemas rather than porting the translation layer forward.

content.ts is 2,500 lines of seed. Do not migrate it wholesale in one pass.

Version-bump resets have no equivalent in Postgres. OPS_STATE_VERSION currently discards saved state whenever the shape changes. Migrations must be additive once data is real — there is no escape hatch.
